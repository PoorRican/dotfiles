# Verification instrument trust

Scope: recognize green results that come from an unrun, mis-scoped, corrupted, or non-reproducible verification instrument.

## Did the check run and observe the claim?

- A filtered test can exit successfully with zero tests; runner status alone is insufficient without a non-zero executed count. Pipelines can mask or manufacture aggregate status, and `grep -c` may return 1 for no matches under `set -e`; individual gate exit statuses are more informative than a final token. (src: false-green-verification-traps, 2026-08-12; mutation-proved-gate-evidence, 2026-09-05)
- A narrow search or empty query is weak evidence for absence: whitespace-specific searches and predicates can miss present variants. Absence claims are stronger when based on positively enumerated matches, values, or populations. (src: false-green-verification-traps, 2026-08-12; failclosed-gate-empty-result-diagnosis, 2026-08-25)
- A Docker interpreter reading a heredoc from stdin can execute nothing and exit zero if Docker did not attach stdin; the `-i` option belongs before the image name. Tests of copied inner code also miss shell expansion in the actual generated payload. (src: docker-heredoc-test-execution, 2026-08-21)
- A CLI stub directory left on persistent `PATH` can shadow the real executable; an unhandled command that exits zero with empty output creates plausible false results. Stub resolution is part of the test boundary. (src: cli-stub-branch-verification, 2026-08-19)
- For a fail-closed control loop, absent/empty state, CLI/API errors, missing configuration, and valid-but-stale state can be confused with health. A stale last-known-good file can leave a dead prober looking healthy; repeated unchanged inputs should not cause repeated writes, and freshness timestamps need to advance as the real writer would. (src: cli-stub-branch-verification, 2026-08-19)
- To prove a refactor leaves outputs unchanged, compare against an immutable snapshot of `HEAD` rather than a stash: `git archive HEAD <pkg> | tar -x -C <dir>`, then run the same probe as a file with `PYTHONPATH=<dir>`, which wins because `sys.path[0]` is the script's directory. Run the probe from a directory that does not itself contain the package: with `python -c`, or a script sitting next to the package, the working-tree copy comes first and both runs silently measure the working tree. Exercised in a disposable repo (the script in a subdirectory printed the `HEAD` value; `python -c` and a script beside the package printed the working-tree value). Never stash a tree that holds other people's uncommitted work. Hash only the invariant outputs, and exclude index arrays that shift when nodes are added. (src: refactor-output-neutrality-probe, 2026-11-10)

## Mutation evidence and safe restoration

- Did the mutation anchor match exactly once, and did the named behavioral test fail for its intended assertion rather than because the program stopped compiling? A no-op mutation tests pristine code; a compile error tests the build, not the invariant. Mutation evidence supports only the property touched by that mutation. (src: false-green-verification-traps, 2026-08-12; mutation-proved-gate-evidence, 2026-09-05; mutation-verified-guarantees, 2026-08-12)
- A pre-mutation working state is a safety precondition: `git checkout -- <file>` restores `HEAD`, not the file's previous dirty contents. It is appropriate only when a clean-tree or checkpoint baseline protects the work; otherwise exact pre-mutation bytes need to be preserved and verified. Restoration and a green rerun are part of the evidence. (src: safe-shell-mutation-testing, 2026-08-23; false-green-verification-traps, 2026-08-12; mutation-verified-guarantees, 2026-08-12)
- A mutation that produces many unrelated failures may have broken the harness or targeted the wrong code, not proved broad coverage. (src: safe-shell-mutation-testing, 2026-08-23)

## Coverage and provenance after change

- A green suite cannot reveal deleted tests or checks. Comparing collected tests by behavior name and checking collection-error counts on both sides makes a test-surface comparison interpretable; a shared editable install can otherwise point the old tree at new source and hide lost coverage. A behavior that changed from raising to warning is not equivalent coverage merely because a replacement check exists. (src: green-suite-blind-spot-audit, 2026-09-04; committed-tree-gate-verification, 2026-09-02)
- A gate may pass only because untracked files exist locally or because a comparison checkout shares an editable install. A clean checkout of the target commit is the relevant reproducibility surface. (src: committed-tree-gate-verification, 2026-09-02)
- For an already-executed script, the executed-copy hash and later committed-copy hash describe different artifacts. Formatting or lint edits do not retroactively change what produced the result; a correction to report text should be distinguished from unchanged computed values. (src: executed-script-lint-provenance, 2026-09-29)
- AST comparison can support a semantics-preserving edit claim only when allowed edit kinds are classified, import side effects are considered, and string-literal values are checked. A post-run correction to report text is distinct from a change in computed values. (src: executed-script-lint-provenance, 2026-09-29)

## Fixtures, comparisons, and baselines

- A frozen numeric fixture with a tight tolerance (atol 1e-6, rtol 1e-5) can encode same-architecture reproducibility rather than the property under test: one fixture failed every case on an x86 GPU host while matching exactly on arm64. Two causes were separable: a contract defect (the trainer's teardown moved the module to CPU before `fit` returned, Lightning 2.6.x) and floating-point order across instruction sets. Find the cause; never loosen the tolerance to get green. (src: frozen-fixture-contract, 2026-09)
- When a parity gate fails, read each failure's reason. A "differs" verdict that came from a comparison exception (several boolean columns with a null maximum difference while a direct comparison found no mismatches) is an instrument defect, and "numeric comparison failed" is not a data verdict; see the data-inspection skill's NumPy dtype traps. A frozen plan's on-failure rule still applies: relaunching first was a recorded deviation. Also smoke final-mode consumers on the first real final artifacts and assert that every final input path exists. (src: gate-instrument-failures, 2026-10-04)
- A receipt that captures stderr (`2>&1`) from the first `uv run --with ...` in a fresh environment records the "Installed N packages" line, so a rerun differs at byte 1. Write receipts from stdout only (or stderr to a separate file) and compare reruns with `cmp`. (src: byte-identical-receipts, 2026-09-25)
- Do not accept an agent's direct calls to pytest test functions as a passing run: pytest caches a fixture within a test, so separate fresh temp directories hid a `FileExistsError` (all tests claimed passing; the real pytest run failed). Require the exact command and the runner's exit status. (src: direct-test-call-false-green, 2026-09-22)
- Env-restoration proof for an isolated harness: capture the baseline after the required runtime imports and before fixture overrides. Some libraries set environment variables on first import (Polars 1.40.1 sets `_RJEM_MALLOC_CONF`), so a pre-import baseline reported a false leak. Find the setter (an audit hook helps), move only the baseline, and never whitelist the key. (src: env-restoration-baseline)
- To adjudicate "did MY change break this gate?" without disturbing a shared tree: `git worktree add --detach <scratch> HEAD`, run the same gate there, remove the worktree, and report the net delta (for example, 2 failures at HEAD against 1 with the change means the change fixed a pre-existing failure). (src: net-delta-gate-adjudication)
- A process supervisor whose log buffers are keyed by a project-scoped process name keeps them across sessions: a reused name returned the previous session's banner, image digest, and tracebacks. Use unique run-scoped names and confirm against the system of record (run listing, build info). (src: supervisor-log-buffer-reuse)
- Workspace gate results depend on where and how the tool is invoked: `ruff check --config packages/pkg/pyproject.toml` from the repo root misclassified first-party imports (pin `[tool.ruff.lint.isort] known-first-party` or run inside the package), and pyrefly cannot see uninstalled workspace members (run it with `--with-editable`). Tool-specific and dated 2026-09; recheck on current versions. (src: workspace-gate-invocation, 2026-09)

## Source-backed fixtures and environment boundaries

- Inspect existing captures before constructing examples; distinguish complete unmodified source objects from helpers and comments. Preserve original response bytes and their digest, request URL, retrieval time and status separately from selected objects and recommendations. A canonicalized-object digest supplements, not replaces, the original-body digest.
- Keep the selected golden population separate from recursively discovered objects; assert case count, deduplicated object count, lineage and key assertions. Retain failed requests, bound and rate-limit probes, retry missing examples within authorized read-only boundaries, and do not infer complete historical coverage from a successful response or exhausted cursor.
- Separate schema migration, source-backed repopulation and runtime adoption. Exercise populated old rows, rerunnable migrations and view parity, then drive captured source through the real receipt and output paths. Label test-only endpoint shells and omitted-field variants; reserialized JSON is not the recorded wire body.
- An offline lock dry run does not prove cached installation. Where permitted, qualify an isolated cached installation and report package selection, interpreter and dependency versions. Distinguish source imports, borrowed-dependency results, installed-wheel qualification and deployed behavior; do not modify borrowed environments. Bind environment settings per command in concurrent sessions.
- Match negative assertions to the intended sanitized diagnostic. If runtime checks are denied, do not bypass the restriction through another runtime or compiler; label permitted static inspection as static evidence. Retain failures and cleanup results, and repeat the complete scenario on final source according to the approved acceptance rule.

## Acquisition timing and completion

- Distinguish application-message delivery time, kernel ingress and original event time. Inline decoding or writing can delay the next receive while bytes queue; timestamp resolution alone does not measure this delay. Preserve clock offset, uncertainty and sample acceptance, and leave unmeasured upstream delay unknown rather than subtracting local decode time.
- Launcher success is not worker completion or evidence quality. Reconcile every planned window, including missed and disabled ones, with completion records, actual files and block records. Retain independently established late artifacts alongside timeout placeholders and investigate discrepancies.
