# Shared checkouts and recovery

Scope: Ownership and preservation when branches, working files or index state may belong to another actor.

## Attribution before recovery

- A path modified at task start is shared or unknown until its changes are attributed; filenames, generated status or small diffs do not establish ownership of its hunks. A path observed dirty and later clean does not establish who changed it. (src: safe-agent-change-rollback, 2026-08-06; shared-repo-artifact-cleanup, 2026-08-04)
- A generated lockfile can contain another actor's dependency changes; being regenerable is not evidence that it is safe to revert. (src: safe-agent-change-rollback, 2026-08-06)
- Branch identity can change between calls in a shared working tree. An expected-branch check bound to the staging/commit mutation is stronger than an earlier observation. (src: shared-checkout-commit-safety, 2026-08-23)
- When `HEAD` is a known, owned stray commit atop a recorded original tip, `git reset --keep <original-tip>` resets the branch and index to that commit and updates the working tree except where non-conflicting tracked work is preserved; it refuses if tracked work would be overwritten. This recovery applies only when the stray commit is identified and the tree is clean or its work has a verified checkpoint; it is safer than `--hard`, not a substitute for recording what should be restored. (src: shared-checkout-commit-safety, 2026-08-23)
- Stay read-only while attributing (fetch is fine; no stash, switch, clean or reset), and judge a leftover local file against upstream by blob, not by diff. `git hash-object <path>` against `git rev-parse origin/<branch>:<path>` shows identity, and `git diff --no-index --numstat <upstream copy> <path>` the size of a difference. For a path untracked at HEAD but present upstream, `git diff --numstat origin/<branch> -- <path>` ignores the worktree file and reports the whole upstream file deleted (`0 55` instead of the real `2 5`). Leftover copies byte-identical to upstream, or to older drafts of it, are common after sessions land work through isolated worktrees and PRs; only paths absent upstream or genuinely divergent are unique work. An upstream deletion of a locally edited file becomes a modify/delete conflict (`git log origin/<branch> --diff-filter=D -- <path>`). The unattributed remainder of a multi-writer diff is usually formatter or generator output, not an unknown owner. (src: attribute-dirty-worktree-to-sessions, 2026-11-08)
- A delegate given worktree-relative paths may write the main checkout instead of its worktree; those uncommitted drafts blocked a later fast-forward (2026-10-01). Attribute such work by diffing added lines against the write and edit bodies in the delegate's transcript, not by timestamps; merge in a scratch detached worktree and land with `--ff-only` behind the collision checks in [dirty-checkout-update.md](dirty-checkout-update.md). (src: relative-path-delegate lesson, 2026-10-01)

## Concurrent writers

- A path that stops resolving while earlier read snapshots still work signals concurrent mutation: another actor staged a mass rename (41 byte-identical renames, 2026-08-17) and reads and globs on the old paths failed. Confirm with `git status --porcelain=v1 -uall` and `git diff --cached --stat`, treat the new path as authoritative, and confirm a pure relocation by matching line counts across old and new paths. Formatter and type-checker config path entries show the live layout. Classify staged hunks against your own before committing. (src: concurrent-relocation lesson, 2026-08-17)
- An unexpected change can come from another agent session rather than from your delegates: a ~331-line feature kept reappearing in files every delegate was forbidden to touch, and it was reverted three times before the writer, a separate session working in the same checkout, was found. Before reverting or blaming a delegate, enumerate writers: `for p in /proc/[0-9]*; do readlink "$p/cwd"; done` filtered to the repository, then the matching process names. Signals: every delegate truthfully denies the change; it reappears within seconds of a clean revert (reappearance means another writer exists, never a stale artifact); a short stability window misleads (26 s did), and a cancelled delegate can land one more write after the cancel returns, so recheck over 60-90 s. (src: concurrent-session lesson, 2026-11-08)
- Treat unexpected changes in unassigned files as the owner's concurrent work: do not revert, "fix" or terminate a peer session. Verify your own deliverable in a detached worktree holding only your files. Never mutation-test shared sources, even with an exact-byte restore: the peer may write during the window and the restore silently reverts their newer work. Do not run a formatter across a shared tree or allow one in delegate briefs; `git diff -w`, or applying the formatter to the base blob, separates pure reformatting from logic changes.
- Prove authorship before reverting anything in a repository you do not exclusively own. Write a timestamped marker file before a risky command: its creation time is an alibi, since files stamped earlier cannot be yours. Check the blast-radius shape (a reformat confined to one sibling crate does not match an unscoped formatter that would sweep the whole workspace) and the diff's character (substantive logic is not formatter output). Resolve a specific PID instead of `pkill -f` patterns, which are far too blunt in a live multi-session environment. (src: authorship lesson, 2026-08-08)

## Branches and ownership

- Owning the changed files does not imply owning the checked-out branch. When the implementation lives in a dedicated worktree, "commit only the related code" follows that worktree, not a reconciled copy on the shared checkout's current branch; a misplaced commit was moved to a recovery ref (2026-09-22). Reconciling files into a shared checkout does not authorize committing on its unrelated branch.
- To move a feature's uncommitted changes from a newer shared branch onto an older one, resolve shared registries and snapshots as the target HEAD plus only the feature's additions, and prove that removing those additions reproduces HEAD. (src: branch-port lesson, 2026-09-22)
- Switching a shared checkout to a newer branch while another actor has uncommitted tracked edits: `git switch -m` can print success and still leave unmerged (`UU`) entries. Pin a snapshot first (`git stash create`, then `git update-ref refs/backup/<topic> <commit>`; see [dirty-checkout-update.md](dirty-checkout-update.md)), then verify `git status`, `git ls-files -u` and HEAD, and resolve preserving both sides. (src: branch-switch lesson, 2026-09-30)
- Do not build an image, publish, or push from a shared checkout holding files you did not write: build contexts and push hooks see the whole working tree. Use a detached worktree at the exact sha (`git worktree add --detach <path> <sha>`), a frozen dependency sync there, and `test -z "$(git status --porcelain)"`, and compare a deployed artifact's checksum with `git show <sha>:<path> | sha256sum`. (src: shared-checkout-build lesson, 2026-09-24)
- A worktree nested inside a checkout and then committed becomes a mode-160000 gitlink, so the outer repository reports `M <path>`. Confirm with `git ls-files --stage`; fix with `git rm --cached -- <path>`, add the folder to the tracked `.gitignore`, and commit. `.git/info/exclude` cannot hide a tracked gitlink. (src: nested-worktree lesson, 2026-11-08)

## Index isolation

- An alternate `GIT_INDEX_FILE` can isolate an owned-only commit from another actor's staged entries, but every command in that operation must use the same alternate index. A mixed worktree path needs an owned-only blob; staging the whole path absorbs foreign hunks. (src: shared-index-isolated-commit, 2026-08-25)
- After an alternate-index commit advances `HEAD`, the real index still describes the previous tree. Realignment is limited to paths proven unstaged before the commit; the foreign staged entries remain the preservation check. (src: shared-index-isolated-commit, 2026-08-25)
- A lock on the main index does not prevent a concurrent branch-ref advance; isolated index promotion also depends on checking the expected-old ref. (src: batch-commit-project-mode-hooks, 2026-09-23)
- The commit recipe for a file that also holds another actor's uncommitted lines, including the compare-and-swap `update-ref`, is in [isolated-index-commit.md](isolated-index-commit.md). A snapshot commit of the whole dirty tree is not a substitute in a shared checkout: it sweeps other actors' edits into history.

## Formatter attribution

- Formatter-only edits are identified by applying the same formatter to the indexed blob (`git show :<path>`) and comparing bytes with the working file; a relative path in the temporary copy preserves path-specific ignore behavior. After `git mv`, the index path holds the original blob even if `HEAD:<newpath>` does not exist. (src: accidental-repo-wide-format-recovery, 2026-08-17)
- Non-source files and files the formatter failed to parse cannot be attributed to that formatter. Quoted or octal-escaped status paths can also defeat naïve extension checks. (src: accidental-repo-wide-format-recovery, 2026-08-17)
- Reconstructing another actor's format-only edits depends on that actor's formatter configuration being in place first; otherwise line-length or per-file rules can change the output. A large mostly-mechanical diff still needs a full residual diff to distinguish semantic edits. (src: concurrent-actor-commit-split, 2026-08-17)

## Dated contribution questions

- When no commit exists on the exact requested date, say so plainly and summarize the nearest relevant branch tips (`git log --all --since=... --until=...`, `git for-each-ref --sort=committerdate`). (src: branch-stack-contribution-summary, 2026-11-08)
- For "what was I committing", keep three categories separate: commits authored by the configured identity; local reflog actions (`commit:`, `cherry-pick:`, `rebase`) as evidence of local work, whose hashes may be ephemeral, so report final reachable hashes first; and other authors' commits present in history.
- In a dirty tree inspect with `git merge-base`, `git log` and `git diff --shortstat` instead of checking out branches or adding worktrees. Compare numbered stacks incrementally against the prior sibling branch, trust the diff and log over a tip commit subject, and call out preservation and snapshot branches instead of treating them as feature branches.
