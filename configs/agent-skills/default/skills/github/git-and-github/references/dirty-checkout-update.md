# Dirty checkout update

A dirty checkout may contain staged intent, unstaged edits, untracked files and local commits belonging to different writers. Do not reset, switch, stash or commit foreign work without coordination.

- Record the branch, HEAD and fetched target; inventory staged and unstaged changes separately, plus untracked and ignored files and deletions. A net diff against HEAD can hide offsetting staged and unstaged changes.
- For tracked unstaged work with a clean index, `git stash create` creates a snapshot without changing the checkout; protect the returned object with a unique backup ref. It does not capture untracked files. Archive and fingerprint those separately. Recheck HEAD and files before mutation.
- Compare the working content with the prospective integration of target and local commits, not target alone. `git merge-tree --write-tree` can construct the prospective tree when conflict-free; an alternate index can represent the working snapshot without changing the shared index. Export `GIT_INDEX_FILE` to every relevant Git command.
- Untracked files can obstruct a merge even when their bytes match files added upstream; autostash does not include them. Do not move foreign files without authorization. If they are safely checkpointed and moved under an approved procedure, verify the resulting tree before removing a backup.
- A non-rewriting merge can preserve local commits, but autostash may conflict on restoration. Keep the checkpoint and verify restoration, untracked hashes, deletions, index and ancestry separately. When both upstream and local edits touch a file, compare with the intended three-way merge rather than requiring the old whole-file bytes.
- A fast-forward over disjoint dirty paths still needs a current HEAD, target and collision check, including paths newly added upstream. Recheck after coordination with writers; verify the resulting HEAD and retained dirty content. If paths overlap, stop unless a separately qualified preservation procedure is authorized.

For a clean index and tracked unstaged changes, record old HEAD `O`, target `TARGET`, and the snapshot `W` protected by a unique ref. After an authorized non-rewriting merge and successful autostash restoration, check both `O` and `TARGET` are ancestors of new HEAD `M`. Compute the expected tracked working tree with `git merge-tree --write-tree --merge-base="$O" "$M" "$W"`; use it only if conflict-free. A fresh `git stash create` snapshot's tree must equal that result (or compare `M^{tree}` if there are no remaining tracked changes). Verify untracked fingerprints, deletions, index and unmerged entries separately.

For a prospective full working snapshot, initialize a private alternate index with `git read-tree "$O"`, add only the initially dirty tracked and intended untracked paths, and run `git write-tree`; export `GIT_INDEX_FILE` throughout. Compare that tree with conflict-free `git merge-tree --write-tree "$O" "$TARGET"` to identify residual work. An equal tree indicates the prospective integration already contains the snapshot, not that it is safe to discard untracked files without checking them.
