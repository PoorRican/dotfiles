# Surface previews

The palette is generated by `nix/modules/desktop-theme.nix`, not stored alongside repository configs. Preview with files from a built Home Manager generation or copy the deployed generated theme beside the scratch config.

## Hyprland

Check option names with `hyprctl getoption <section:key>`. Apply an edited Lua block with `hyprctl eval`, omitting leading and whole-line `--` comments: a leading `--` is interpreted as a command-line flag. An extracted block cannot see locals defined earlier in `hyprland.lua`; supply needed locals, including the palette from `~/.config/hypr/desktop-theme.lua`. Check the applied options and `hyprctl configerrors`. Changes persist until reload.

## Waybar

Stop `hypr-waybar.service`, copy the edited `configs/waybar/style.css` and deployed `~/.config/waybar/theme.css` into a scratch directory, then start a transient preview using the repository JSONC config and scratch stylesheet. The stylesheet imports `theme.css` relative to itself. Re-copy the stylesheet after editing; the watcher follows the scratch copy. Alternatively use both files from a built generation.

```sh
P=$(mktemp -d "${SCRATCH_DIR:-$PWD}/waybar-preview.XXXXXX")
cp ~/.config/waybar/theme.css configs/waybar/style.css "$P/"
systemctl --user stop hypr-waybar.service
systemd-run --user --unit=cbox-waybar-preview --collect waybar \
  -c "$PWD/configs/waybar/config.jsonc" -s "$P/style.css"
journalctl --user -u cbox-waybar-preview --no-pager -o cat
```

With `reload_style_on_change` enabled, CSS changes reload automatically; JSONC changes require restarting the preview or `systemctl --user kill -s SIGUSR2 cbox-waybar-preview`. Gate a new module with a short throwaway run (`waybar -c <scratch-config> -s /dev/null -l info`) and check its output or the journal for `Unknown module|Disabling`. The fullscreen edge-reveal helper targets the managed service, not the transient preview, so assess its behavior after deployment. Stop the preview unit before reloading Hyprland or ending the preview.

## rofi

If an agent-shell launch does not map, use a transient unit. `config.rasi` selects the generated `desktop` theme; preview a repository theme explicitly with `-theme`, or use the built generation's `themes/desktop.rasi`.

```sh
systemd-run --user --unit=rofi-preview --collect --working-directory=configs/rofi \
  rofi -show drun -config ./config.rasi -theme ./themes/<theme>.rasi
# Capture feedback, then stop the preview.
systemctl --user stop rofi-preview
```

## dunst

Build the Home Manager generation, then load its rendered config and send samples:

```sh
dunstctl reload "$(readlink -f "$gen/home-files/.config/dunst/dunstrc")"
notify-send -u low "preview" "low"; notify-send "preview" "normal"; notify-send -u critical "preview" "critical"
dunstctl close-all
```

## Ghostty and hyprlock

- For Ghostty, back up or record any configuration and theme links replaced by preview copies. Validate with `ghostty +validate-config` and reload windows with `pkill -USR2 -x ghostty`. Restore the originals before switching generations to avoid activation collisions.
- For hyprlock, give the user `hyprlock -c ~/dotfiles/configs/hypr/hyprlock.conf`; do not lock their session yourself.

For screenshots, obtain bar geometry from `hyprctl layers -j` before using `grim -g`; `grim -s 0.5` captures the full screen at half scale. Show the user the result for feedback.

## Build and deploy

To avoid building unrelated work from a shared checkout, create a detached worktree at `HEAD`, copy in only the owned changes, and stage new files there so the Git-backed flake can see them. Build the generation and inspect its generated `home-files`, including palettes, before removing the worktree.

```sh
W=$(mktemp -d "${SCRATCH_DIR:-$PWD}/dotfiles-head.XXXXXX"); rmdir "$W"
git worktree add --detach "$W" HEAD
# Copy owned changes into $W, then stage their explicit paths.
git -C "$W" add <owned-paths>
gen=$(nix build "$W#homeConfigurations.cbox.activationPackage" --no-link --print-out-paths)
```

After approval, commit only owned paths; isolate owned hunks if a file also has unrelated changes. Compare the built generation with the active one for unrelated drift. Stop transient preview units and restore any Ghostty preview files before `home-manager switch --flake .#cbox`; report activation collisions rather than forcing a switch.

Start `hypr-waybar.service` and reload Hyprland only after the preview bar has stopped. Check that live config links resolve to the new generation and `hyprctl configerrors` is empty. A changed user-service unit requires `systemctl --user daemon-reload`; a service reading a symlinked config may also need restarting.
