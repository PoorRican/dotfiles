# cbox lock and idle

`configs/hypr/hyprlock.conf` and `hypridle.conf` are linked by Home Manager. `bin/hypr-idle` resolves `XDG_RUNTIME_DIR` from the Hyprland process environment and `WAYLAND_DISPLAY` from its `wayland-N` socket, then starts `hypridle`; listener commands inherit that environment and need both variables to reach the compositor. `hypr-idle.service` is reasserted on Hyprland start and reload. Hyprland locks on session start, not configuration reload. The cbox configuration uses `/usr/bin/hyprlock` (a Nix-store binary aborted on EGL on this host); `bin/cbox-setup-hyprlock-pam` installs `/etc/pam.d/hyprlock`. General authentication, binary, DPMS and inhibitor pitfalls are covered by the `workstation-and-agent-tooling` skill.

Hypridle accepts `general` and `listener` blocks; a top-level timeout form can register zero rules without the intended actions. The cbox configuration uses `ignore_systemd_inhibit = true` so agent-held logind idle inhibitors do not suppress its timers. Inspect the daemon journal and inhibitors when diagnosing skipped actions.

After an approved Home Manager switch, run the PAM installer when needed (it requires root), reload user units if changed, and restart `hypr-idle.service`; a changed configuration symlink does not prove the running daemon loaded it. Check its active PID and start time. Do not restart the Hyprland session as a routine deployment step; safe-mode recovery may need a user-approved session restart. Arrange an escape path before the user tests a lock; from a TTY or SSH, `pkill -u $(id -u) hyprlock` can terminate a wedged lock. Use `hyprctl locked -j` to check lock state rather than inferring it from the display.

To investigate an inhibitor regression without changing live timers, run a bounded second hypridle with a scratch config and a listener that touches a marker, under `systemd-inhibit --what=idle --mode=block`. In the probe set `ignore_dbus_inhibit = true` to avoid taking the live ScreenSaver bus name, `ignore_wayland_inhibit = true` to isolate the systemd variable, and `inhibit_sleep = 0`. Compare the production `ignore_systemd_inhibit` setting with its opposite; require an actual Idled event or treat the result as inconclusive. Clean up the probe; do not execute the real lock, DPMS or suspend actions for this test.
